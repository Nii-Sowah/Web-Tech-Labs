Forms

The <form> element is a landmark containing interactive controls for submitting information. With plain HTML - no JavaScript required - you can enable users to enter data, validate it client-side, and submit it to a server.

HTML attributes can require a field, define what a valid value looks like, and block submission until the data matches. All of this is called constraint validation, and it happens automatically unless disabled with novalidate.

Submitting forms

A form submits when a submit button inside it is activated:

<input type="submit" value="Submit Form">
<button type="submit">Submit Form</button>

Two attributes on <form> control where the data goes:

AttributePurpose
actionURL that processes the submission (defaults to the current page)
methodGET appends data to the URL as a query string; POST sends it in the request body (always use POST for sensitive data)

Only named form controls are submitted, as name=value pairs. A control's value comes from its value attribute or whatever the user typed/picked. Unselected checkboxes and radio buttons are left out entirely.

There's also a third method, dialog: submitting a form inside a <dialog> closes it without sending or clearing the data.

Radio buttons & checkboxes

Radio buttons

Giving a group of radio buttons the same name makes them mutually exclusive - selecting one deselects the others in that group. Add checked to preselect one, and required on at least one to force a choice.

Checkboxes

Checkboxes can safely share a name too only the checked ones submit. Always give each one an explicit value, or every checked box submits the unhelpful default value on.

Labels & fieldsets

Every form control needs a <label> so users - especially screen reader users - know what's expected. Labels also expand the clickable "hit area" of a control.

<!-- explicit -->
<label for="full_name">Your name</label>
<input type="text" id="full_name" name="name">

<!-- implicit -->
<label>Your name
  <input type="text" name="name">
</label>

A group of controls - like a set of radio buttons - needs its own label too. That's what <fieldset> and <legend> are for:

<fieldset>
  <legend>Who is your favorite student?</legend>
  <label><input type="radio" name="machine" value="hoover"> Hoover</label>
  <label><input type="radio" name="machine" value="toasty"> Toasty</label>
</fieldset>

Built-in validation

Certain attributes create client-side constraints that block submission until satisfied:

AttributeWhat it checks
requiredA value must be present
min / maxNumeric, date, or time value must fall in range
minlength / maxlengthText length bounds
patternValue must match a regular expression
typeValue must be a valid email, URL, number, etc.

CSS pseudo-classes track this state live: :required, :optional, :valid, :invalid, :in-range, and :out-of-range update as the user types. The browser's own error messages, though, only appear at submission time.

Avoid styling a submit button to look disabled with form:invalid [type="submit"] { pointer-events: none; } - it blocks the constraint validation messages many users rely on to understand what's wrong.

HTML APIs & the DOM

The DOM (Document Object Model) is the tree of node objects - elements, attributes, and text - that make up a loaded page. The parallel AOM (Accessibility Object Model) exposes that same tree to assistive technology.

Every element type has a matching JavaScript interface for reading and changing it. For example:

let allImages = document.querySelectorAll('img');
allImages.forEach((img) => console.log(img.alt));

These interfaces inherit from one another: HTMLImageElement and friends inherit from HTMLElement, which inherits from Element, which inherits from Node, which inherits from EventTarget - the source of addEventListener().

InterfaceRepresents
NodeAny tree node provides firstChild, appendChild(), cloneNode()
DocumentThe loaded page itself document.body, document.cookie
WindowThe browser tab/window resizeTo(), devicePixelRatio
